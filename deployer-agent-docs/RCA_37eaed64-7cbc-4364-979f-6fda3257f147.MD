# RCA — Deploy failed at `deploy_k8s` / health_check (run 37eaed64-7cbc-4364-979f-6fda3257f147)

## Symptom
Deployment never became ready; nginx `/health` returned `connect() failed (111: Connection refused)` to `127.0.0.1:8001` because the FastAPI backend crashed on startup and never bound port 8001. K8s rollout timed out → `deploy_k8s` failed (not retryable).

## Root cause (confirmed from source in eph sandbox)
The app is built on **PostgreSQL (SQLAlchemy + asyncpg)** and is designed to talk to an **external Supabase Postgres** (see comment in `backend/lib/database.py`: "compatible with Supabase's PgBouncer pooler"). There is **no MongoDB wiring anywhere** in the backend (grep for motor/AsyncIOMotor/MongoClient/MONGO_URL returns nothing) even though the deployment template is `fastapi_react_mongo_shadcn_base_image`. Emergent production provides managed **MongoDB Atlas**, not PostgreSQL.

The backend startup hook crashes:
- `backend/server.py:2077-2081` — `@app.on_event("startup")` → `ensure_preview_database()`.
- `backend/services/preview_database.py:33` — raises `RuntimeError: The configured preview PostgreSQL runtime is unavailable` because `pg_ctl` (at `PREVIEW_POSTGRES_BIN=/usr/lib/postgresql/15/bin`) is not present in the production runtime image.

Why it reaches that code in production: the preview `backend/.env` was carried into the deploy and contains preview-only values that become production secrets:
```
DATABASE_URL=postgresql+asyncpg://mera_preview:***@127.0.0.1:5432/mera_preview   # local preview Postgres — does not exist in prod
PREVIEW_POSTGRES_DATA=/app/.local/postgresql
PREVIEW_POSTGRES_BIN=/usr/lib/postgresql/15/bin
PREVIEW_RUNUSER=/usr/sbin/runuser
```
`_start_preview_database()` only returns early when `PREVIEW_POSTGRES_DATA` is **unset**. Because it IS set in prod, the code tries to boot a local Postgres, finds no `pg_ctl`, and raises.

This is a cascading fault — even if `ensure_preview_database()` were bypassed, the next startup steps (`init_db()` and `async_session_maker()` in `backend/lib/database.py`) would fail identically, because `DATABASE_URL` points at `127.0.0.1:5432` where no Postgres is running in the production container.

## Why this is not fixable here
- Not a manifest problem — `Dockerfile`/`nginx.conf`/`entrypoint.sh` are correct; the backend process itself exits.
- Re-running `resume_pipeline` on the same source fails identically (verified root cause is deterministic startup crash).
- The eph sandbox has no production Postgres and no secrets, so a full boot cannot be reproduced; the fix depends on provisioning an external DB + setting prod secrets, which is outside the deployer's control.

## Required fix (owned by E1 + the user)
The app needs a real, externally-reachable PostgreSQL in production. Two parts:

1. **Provision an external managed Postgres** (the code targets Supabase; Neon/RDS/any managed PG also works). This is a user/third-party action — Emergent production does not run PostgreSQL.

2. **Code / config changes (E1, in source):**
   - Make the preview-Postgres bootstrap prod-safe: `ensure_preview_database()` / `_start_preview_database()` must be a no-op outside preview. Simplest: do NOT ship `PREVIEW_POSTGRES_DATA`, `PREVIEW_POSTGRES_BIN`, `PREVIEW_RUNUSER` to production (remove them from `backend/.env` before deploy, or guard the startup call behind an explicit preview-only flag). With `PREVIEW_POSTGRES_DATA` unset, `_start_preview_database()` returns immediately.
   - Point `DATABASE_URL` at the external Postgres instead of `127.0.0.1:5432`. The engine in `backend/lib/database.py` already switches to `ssl="require"` when `PREVIEW_POSTGRES_DATA` is unset, which is what a hosted Supabase/Neon URL needs.

3. **Secrets (user, Deployment Panel → Secrets):** after provisioning, set the production `DATABASE_URL` secret to the external connection string (SSL-enabled). Note: the value picked up from preview `.env` points at the dead `127.0.0.1:5432` and must be overwritten in the UI; pre-existing secret values are not overwritten on redeploy.

Once an external `DATABASE_URL` is set and the preview-Postgres bootstrap is disabled in production, redeploy.

## Evidence
- Traceback: `server.py:2081` → `preview_database.py:57` → `preview_database.py:33` `RuntimeError: The configured preview PostgreSQL runtime is unavailable`.
- Startup log: `🔌 Connecting to Postgres at 127.0.0.1:5432` then `Backend died, shutting down nginx...`.
- `backend/requirements.txt`: `asyncpg`, `SQLAlchemy`, `alembic` (Postgres stack). `motor`/`pymongo` present but unused.
- No Mongo client code anywhere in `backend/**.py`.
